case study: NYC 311

AI built fast. I decided what was true.

I work with AI (I use claude code and cursor) to develop something that not only works but also looks well-designed. here is where I stepped in on the NYC 311 map, one decision at a time.

  1. 01from static to story

    my original tableau workbook was static. now the story unfolds, part by part, under a user’s touch as they scroll. it helps them feel connected to the information they’re consuming and keeps it bite-sized.

  2. 02a map underneath

    the first version had no map underneath, only zip codes pinned in space. so I had map line art fade in beneath to keep things understandable.

  3. 03spikes become lines

    I asked for the solid, round-capped lines from my dissertation timeline, in the 311 colors.

  4. 04made for a phone

    on my phone the map was strangely aligned with the bottom of the screen and very small. it didn’t have the same punch as the desktop version, so I added zoom controls.

  5. 05labels that matter

    the three tallest lines now show their zip code for every complaint type, so the story reads at a glance.

  6. 06an honest scale

    AI tends to hallucinate unless you prompt it directly to fix an issue. since we were working with data, I didn’t want anything misconstrued to the public, so I went through every screen and picked apart what wasn’t the most honest way to display information.

the all-four view had given each type its own scale, making 47 mold complaints look as tall as 37,141 heat complaints. now one shared scale keeps every line comparable. see the 311 project →

what stays mine

the creative process. I never use auto AI website builders that make the product from A to Z. once I have a project about 60% built with my own tools, that’s when I start working with AI to bring it to the next level. and finicky attention to detail: claude doesn’t open the laptop at 4am because one of the buttons is overlapping something it shouldn’t. I do. every number on my 311 page comes straight from my tableau workbooks.

accuracy as a habit

in “reframing the same body” I used a year of my own ultrahuman ring data and left every number alone. I changed only the design choices: ordering, scale, color and the treatment of missing data, so the same body read as declining in one version and as progress in the other. values changed: 0.

data doesn’t speak for itself, it’s always arranged, filtered and framed. I check my own work for that. see the experiment →

remi, an interface

I wireframed every remi screen in adobe illustrator, like I would have done before AI, so I had a reliable backbone made by me. then I built a clickable version, because you don’t know how the user flow will go until you’ve experienced it yourself. the flow wasn’t as smooth as it looked in the flats, so I reworked parts of the prototype until it led smoothly from A to B. try remi →

a design language

this site runs on a swiss style, helvetica-forward minimalist design system so the work can shine. its colors, font and spacing live in one set of variables at the top of the stylesheet, so one change restyles every page.

explaining complicated things

at UPMC I built a power BI homepage for the HEDIS production team. I grouped all the sources, their breakdowns and their titles in an excel sheet, then linked them to clickable buttons in power BI so the reports were easy to reach. the team responded overwhelmingly positively and said they’d keep using it after my summer internship ended.

I also wrote documentation the team adopted for its azure DevOps migration. and for presenting, at FIT I showed wireframes, UI/UX and product designs on 11x17 decks with moodboards, preliminary sketches, a first round of design and refinements, then sat through hours of critique so people could say how to improve the work.
